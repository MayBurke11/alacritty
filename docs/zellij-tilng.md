# Тайлинг в Zellij: базовая раскладка панелей

## Как это работает с точки зрения пользователя

Тайлинг в Zellij — это способ организовать панели на экране так, чтобы они **не перекрывались**, а делили доступное пространство между собой. Всё управление тайлингом происходит через два режима: **Pane** (создание/закрытие/навигация) и **Resize** (изменение размеров).

Базовые понятия:

- **Панель (pane)** — минимальная единица. В панели работает терминал, редактор, команда или плагин.
- **Контейнер** — логическая группа панелей. Задаёт направление раскладки: горизонтально или вертикально.
- **Корневой контейнер** — вся вкладка (tab). По умолчанию раскладывает панели горизонтально.

---

## Как Zellij раскладывает панели

Zellij использует **рекурсивное бинарное деление пространства**. Каждый контейнер делит своё пространство между детьми — либо горизонтально (рядом), либо вертикально (друг над другом).

### split_direction

- **`"horizontal"`** (по умолчанию) — дети располагаются слева направо
- **`"vertical"`** — дети располагаются сверху вниз

```
Горизонтальный контейнер:          Вертикальный контейнер:
┌─────┬─────┬─────┐               ┌───────────────┐
│     │     │     │               │               │
│  1  │  2  │  3  │               │       1       │
│     │     │     │               │               │
└─────┴─────┴─────┘               ├───────────────┤
                                  │       2       │
                                  ├───────────────┤
                                  │       3       │
                                  └───────────────┘
```

## Вложенность

Тайлинг строится рекурсивно: каждый `pane` может быть либо **терминальной панелью** (с shell/командой/редактором), либо **контейнером** (с детьми и `split_direction`).

Пример: три панели, где правая часть разделена вертикально:

```kdl
layout {
    pane split_direction="vertical" {
        pane
        pane split_direction="horizontal" {
            pane
            pane
        }
    }
}
```

Визуально:

```
┌───────────────────────┬──────────────┐
│                       │              │
│                       │              │
│          pane         │    pane      │
│                       │              │
│                       ├──────────────┤
│                       │              │
│                       │    pane      │
│                       │              │
└───────────────────────┴──────────────┘
```

Корневой `layout` — это неявный горизонтальный контейнер. Внутри него — `pane split_direction="vertical"`, который делит экран по вертикали на две части. Правая часть — ещё один `pane` с `split_direction="horizontal"`, который делится на две панели.

## Вложенность контейнеров

Чтобы сделать сложную раскладку, контейнеры вкладываются друг в друга. Каждый контейнер сам решает, как делить своё пространство между детьми.

**Пример: три панели — левая большая, правая разделена по вертикали на две**

```kdl
layout {
    pane split_direction="vertical" {
        pane
        pane split_direction="horizontal" {
            pane
            pane
        }
    }
}
```

Визуально:

```
┌───────────────────────┬──────────────┐
│                       │              │
│                       │    pane      │
│        pane          │              │
│                       ├──────────────┤
│                       │              │
│                       │    pane      │
│                       │              │
└───────────────────────┴──────────────┘
```

Корневой `layout` делит экран горизонтально на две части. Левая часть — одна панель. Правая часть — контейнер с `split_direction="vertical"`, который делит своё пространство на две панели сверху вниз.

### Вложенность

Контейнеры можно вкладывать сколько угодно раз. Каждый уровень вложенности делит пространство своего родителя.

**Пример: четыре панели — две сверху, две снизу**

```kdl
layout {
    pane split_direction="vertical" {
        pane split_direction="horizontal" {
            pane
            pane
        }
        pane split_direction="horizontal" {
            pane
            pane
        }
    }
}
```

Визуально:

```
┌──────────┬──────────┐
│          │          │
│  pane 1  │  pane 2  │
│          │          │
├──────────┼──────────┤
│          │          │
│  pane 3  │  pane 4  │
│          │          │
└──────────┴──────────┘
```

### Как читать вложенность

Правило простое: **каждый `pane` с детьми — это контейнер. Он делит своё пространство между детьми.**

```kdl
layout {
    pane split_direction="vertical" {  // контейнер: делит пространство по вертикали
        pane                            // ребёнок 1 — терминальная панель
        pane split_direction="horizontal" {  // ребёнок 2 — контейнер, делит по горизонтали
            pane                        // внук 1
            pane                        // внук 2
        }
    }
}
```

Разбор по шагам:

1. `layout` (неявный horizontal) → два ребёнка
2. Первый ребёнок — `pane split_direction="vertical"` → контейнер, делит своё пространство по вертикали
   - Верхняя часть — терминальная панель
   - Нижняя часть — контейнер `split_direction="horizontal"`
3. Внутренний контейнер делит нижнюю часть по горизонтали на две панели

### size — управление пропорциями

По умолчанию все панели в контейнере делят пространство поровну. `size` позволяет задать фиксированный размер или процент.

**Проценты:**

```kdl
layout {
    pane size="30%"  // 30% ширины
    pane size="70%"  // 70% ширины
}
```

**Фиксированные значения (в символах):**

```kdl
layout {
    pane size=80  // 80 символов ширины
    pane          // всё остальное
}
```

**Смешанный пример:**

```kdl
layout {
    pane split_direction="vertical" {
        pane size="80%"  // 80% высоты
        pane size="20%"  // 20% высоты
    }
}
```

Визуально:

```
┌──────────────────────────────┐
│                              │
│          80%                 │
│                              │
├──────────────────────────────┤
│           20%                │
└──────────────────────────────┘
```

### Команды и редактор в панелях

Панель не обязана быть просто shell. Можно сразу запустить команду или открыть файл на редактирование.

**Запустить команду:**

```kdl
layout {
    pane command="htop"
    pane command="tail" {
        args "-f" "/var/log/syslog"
    }
}
```

**Открыть файл в редакторе:**

```kdl
layout {
    pane edit="src/main.rs"
    pane edit="Cargo.toml"
}
```

**Смешанный пример:**

```kdl
layout {
    pane split_direction="vertical" {
        pane edit="src/main.rs"     // редактор сверху
        pane command="cargo" {       // сборка снизу
            args "run"
            focus true               // эта панель будет в фокусе при старте
        }
    }
}
```

### Параметры панелей

| Параметр | Описание | Пример |
|---|---|---|
| `split_direction` | Направление деления контейнера | `"horizontal"` / `"vertical"` |
| `size` | Размер панели (процент или фикс.) | `"50%"` / `80` |
| `command` | Команда для запуска вместо shell | `"htop"` |
| `args` | Аргументы команды | `"-f" "/var/log/syslog"` |
| `edit` | Файл для открытия в редакторе | `"src/main.rs"` |
| `cwd` | Рабочая директория | `"/home/user/project"` |
| `focus` | Фокус при старте | `true` / `false` |
| `name` | Заголовок панели | `"my pane"` |
| `borderless` | Без рамки | `true` / `false` |

### Как Zellij выбирает, куда вставить новую панель

Когда вы создаёте новую панель через `Ctrl + g` → `Ctrl + p` → `n` (или `d`/`r`), Zellij:

1. Берёт **текущую (фокусную) панель**
2. Если она в контейнере — делит этот контейнер, вставляя новую панель рядом
3. Если направление не указано (`n`) — выбирает наибольшее доступное пространство
4. Если указано `d` (down) или `r` (right) — вставляет в соответствующем направлении

### Полезные примеры

**Две панели рядом:**

```kdl
layout {
    pane  // 50% слева
    pane  // 50% справа
}
```

**Две панели друг над другом:**

```kdl
layout {
    pane split_direction="vertical" {
        pane  // 50% сверху
        pane  // 50% снизу
    }
}
```

**Три панели: навигатор + редактор + терминал:**

```kdl
layout {
    pane split_direction="vertical" {
        pane size="20%" command="lf"  // файловый менеджер
        pane split_direction="horizontal" {
            pane edit="src/main.rs"     // редактор
            pane command="cargo" {      // сборка
                args "run"
            }
        }
    }
}
```

```
┌───────────────────────┬──────────────────┐
│                       │                  │
│     lf (20%)         │   src/main.rs    │
│                       │                  │
│                       ├──────────────────┤
│                       │                  │
│                       │  cargo run       │
│                       │                  │
└───────────────────────┴──────────────────┘
```

### Как Zellij выбирает, куда вставить новую панель

Когда вы создаёте новую панель через `Ctrl + g` → `Ctrl + p` → `n` / `d` / `r`:

- **`n`** (New) — вставляет панель в наибольшее доступное пространство
- **`d`** (Down) — делит текущую панель по вертикали, новая снизу
- **`r`** (Right) — делит текущую панель по горизонтали, новая справа

Zellij не использует заранее заданную сетку. Каждое создание панели — это **деление существующего пространства**. Это бинарное дерево, а не таблица.
